# Codex Mesh

通过 Hub 将工作交给用户已配对的电脑。把远端节点视为有独立权限边界的 Codex 执行环境。

## 分派任务

1. 先调用 `mesh_list_nodes`，确认节点在线、标签匹配、工作区已登记且能力合适。不要凭记忆猜测节点 ID 或工作区。
2. 根据请求选择执行方式：
   - 指定机器：使用确切节点 ID。
   - 按能力选择：使用标签、操作系统和在线状态选择器。
   - 相互独立的检查：使用 `parallel`；需要最快一台接单时使用 `first_available`。
3. 默认调用 `mesh_start_readonly_task`。在 `prompt` 中写清目标、预期产出和验证方式；所有任务都必须从 `mesh_list_nodes` 的结果中选择已登记的 `workspace_id`，不能省略或自行编造。
4. 仅在用户明确要求修改文件时调用 `mesh_start_workspace_task`。必须明确填写一个 `node_id` 和一个 `workspace_id`，并在提示中限定修改范围。不要让多台节点同时写同一工作区；需要并行修改时先隔离 Git 分支或 worktree。
5. 用 `mesh_get_task` 跟踪状态并汇总各节点结果。任务进入等待审批或等待输入状态时，把请求原样、清楚地交给用户决定。
6. 任务不再需要时调用 `mesh_cancel_task`；说明取消不会回滚已经发生的修改或外部副作用。

## 配对节点

仅在用户要求加入新电脑时调用 `mesh_create_pairing`。使用短有效期，把配对码视为临时秘密，只交给预期节点；不要写入日志、仓库或共享记忆。

## 守住权限边界

- 不把 Codex Mesh 当作任意远程 Shell。只能通过已公开的 Mesh 工具创建和管理受限任务。
- 不尝试访问未登记路径、提升权限、关闭沙箱、绕过远端审批或改变节点本地策略。节点本地策略始终优先，主控只能进一步收紧权限。
- 不把只读任务用于安装软件、写文件、推送 Git、部署、重启服务或其他会改变状态的操作。
- Hub 或节点拒绝操作时，报告可安全公开的错误并调整任务范围；不要通过换提示词、换节点或拆分命令规避拒绝。
- 不在任务提示、元数据或记忆中放入口令、令牌、私钥、Cookie 或其他凭据。需要秘密时只引用远端已配置的秘密名称。

## 使用共享记忆

先调用 `mesh_search_memory` 获取与项目有关的稳定背景，再开始需要跨设备上下文的任务。

仅当用户明确要求或确认保存时调用 `mesh_add_memory`。只保存可复用的事实，例如项目约定、架构决策、已验证的故障结论和用户偏好；选择最窄作用域，例如 `project/<id>`。附上有帮助的标签、来源任务或版本元数据，并为临时事实设置过期时间。若同时提供 `scope` 和 `key`，同名记忆会被覆盖；覆盖前必须先搜索并取得用户确认。

不要保存凭据、原始私人对话、完整日志、未经验证的推测或节点本地路径。敏感但确有必要的信息标记为 `sensitive`；秘密只保存类似 `vault://node/name` 的引用，不保存实际值。发现冲突记忆时保留来源并请用户决定，不静默覆盖。
